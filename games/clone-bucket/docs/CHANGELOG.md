# Changelog — superseded pre-recovery claims

## 2026-11-08 — 1.0.0: renamed to clone-bucket

Renamed to clone-bucket (`io.dev.clone-bucket`), version reset to 1.0.0. The project targets iOS, desktop and WebGL. It has no ads, in-app purchases, attribution SDKs or Android support.

All debug code was removed the same day: the dev screens (`DebugScreen`, `ABVariablesScreen`), the FPS overlays, the "complete level" and debug buttons on the game screen, the debug level and ball overrides, the CrazyLabs debug tools and TTP log console, test scripts, and every debug-only log. The full list is in doc 09 §3.8.

Correction, same day: the green » button on the game screen (`CompleteLevelBtn`, `GameScreen.OnClickComplete`) is not debug code. In the original it slides in when the target is reached and lets the player continue at once. It was removed with the debug code by mistake and is restored. The game-screen header (chunk tracker, star bar, star panel) now follows the original logic recovered in `tools/recovery/recovered/R6_header_ui.md`.

Level-complete screen, same day: the balls counter and the game screen's star arc were drawn over the complete screen's stars and title. They sit on a second root canvas, and the rebuild never turned the game screen off when the level completed. `CompleteLevel` and `GameScreen.OnDisable` now follow the original (`tools/recovery/recovered/R7_level_end_and_start.md`). The complete screen also now shows the real level number (it always said "Level 8"), this level's score, the third star when it is earned, and keeps the coin panel visible. The physics pause is not used (R7 §6). The old-title card is covered in the next entry.

Level-end title card, same day: the black card with the logo, confetti and fireworks (`EndBlack`) is shown again for the 2 s between a win and the complete screen, as in the original. `GameManager` turns it on in `CompleteLevel` and hides it when the complete screen opens and on `Reset`. The confetti sound (`AudioManager.PlayConfetti`) stays unused, because the original never plays it (R7 §6).

Tap to start, same day: the first tap now plays the original's transition (`GameManager.StartPlay` and `MainScreen.Close`, `tools/recovery/recovered/R7_level_end_and_start.md` §5). The main screen's title, gems counter and shop button fade or slide out over 0.5 s and the settings button zooms out over 0.3 s, instead of the whole screen shrinking over 0.2 s while the game screen appeared under it. The game screen opens only after the main screen has gone, and a second tap during the close is ignored. Reopening the main screen puts each element back to the position, scale and colour it had before the close; the rebuild takes that snapshot once, in `MainScreen.Awake`. The original replays a short intro when the main screen reopens (settings button, gems texts and shop button); the rebuild does not, and the ball-buff buttons are not in the rebuild. The level-1 tutorial hint is still shown by `ShowGameScreen` after the tap, which differs from the original (R7 §5.3).

Start screen details, same day: four more differences from the original's start screen are ported (`tools/recovery/recovered/R7_level_end_and_start.md` §5.2 to §5.7). Reopening the main screen replays the original's intro in `MainScreen.OnEnable`: the settings button zooms in and the gems texts and icon fade in over 0.3 s, and the shop button slides in from 250 units to its left over 0.5 s. The tutorial hint now follows the original rule: `Reset` shows it on every level, and the first tap hides it; `ShowGameScreen` no longer touches it, and the swipe-loop script no longer checks for level 1. The balls counter counts up to its target after the tap, as the original does: `SetBalls` sets the target only, and `GameScreen.Update` moves the shown count toward it (the rounding is inferred from the recovered instructions). `RestartGame` now returns to the start screen, with the main screen and the hint on, and waits for a tap, as the original does; it used to open the game screen at once. The original's ad-linked event is not ported, because the rebuild has no ads. Corrections to the entries above: the shop-button slide and the complete-level button slides now move in the original's direction (the helper had them reversed), and the title's scale is still restored on reopen, although no recovered code restores it in the original (kept, so the title stays visible). Open: the scene's `Tutorial` component is disabled, so the hint's finger loop does not run, and the original `Reset` does not clear `GameStarted` (R7 §5.8).

Playtest fixes, same day: four bugs found in play-testing are fixed. The RESTART button on the fail screen is now centred; it sat on the left because the removed ad button had been on the right (R7 §5.9). After a fail and a restart, the maze no longer stops rotating for the rest of the session; the touch input now shares its finger state across levels, as the original does (R7 §5.9). Chains no longer drift with the maze: each link keeps its pitch and yaw and loses its roll, as in the original (`tools/recovery/FINDINGS.md`, Locks). The bucket glow no longer appears as a white rectangle over the cup: it spawns above the bucket under the level, as in the original (`tools/recovery/recovered/R2_levels_bucket_chains.md`). The original's glow animation is not yet ported.

Second playtest round, same day: the round-one fix for the frozen maze was not enough. Restart runs on the same frame that the old level's touch component is swapped for the new one, so the single "finger up" event could be lost, and the maze then ignored every drag until the game was closed. The touch shim now reads the screen every frame, as the real Lean Touch does, and touches take priority over the simulated mouse (`tools/recovery/FINDINGS.md`, Controls). The "-20" gate ate every ball because its value was set again every frame, so it never ran out. In the original the value is set once; an empty gate hides itself, and the ball is not removed, as in the original `SubGate.Sub` (R1 §2.7). Each removed ball now takes its full ball value from the total, as the original does (`SubtractTotal(BallData.value)`), so a "-20" gate can remove more than 20 points' worth at higher tiers. Rotation now follows the original's Lean Touch pattern: the maze turns with the finger at once and then eases, and the boss rotation targets turn with the finger too (R3b, R3_rotation_camera). When a level starts, the `GameManager` rotation values (3 and 20) overwrite the prefab values (3.5 and 16), as in the original, so the live pair is 3 and 20 (`docs/02_GAMEPLAY_MECHANICS_SPEC.md` §1.2). Bucket collect effects that are despawned now move under the pool, and the pool is cleared before a new level is built. A level clear therefore no longer leaves destroyed objects that the next spawn reuses (the `MissingReferenceException`). Boss levels spawn their balls even though their prefabs leave the balls parent unset, as the original does (scene root). Ball skins turn with the ball's Z rotation, and multiplier clones appear around the gate the ball touched, not on the ball, and no longer copy its speed. Balls take their material from the colour scheme. The ParticleImage shim's namespace is fixed, so 31 UI particle effects (the star burst, the star bar, the gem and coin effects and the skin sparkles) draw again. The missing-script test had passed because the script reference resolves, which is not the same as the class loading at runtime (`docs/10_ENGINE_BASELINE_CHECK.md`). Two rows of the level table are both named `BossLevel1`; the first row wins, as in the original, so only the analytics mission index was affected.

Tools folder, same day: the whole top-level `tools/` folder is now git-ignored and has been removed from this branch's history; its records (FINDINGS.md, the recovered write-ups, scripts, checksums and stub-remap.csv) stay on disk, and the local branch `backup/pre-tools-purge` keeps the earlier commits that contained them.
