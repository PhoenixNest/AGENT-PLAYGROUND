## Fix

Route: transplant the `shop_gift_claimed` banner subtree onto the other shop templates inside `HomeChrome.UseClaimedGiftBanner`. Playwright was not run. The outer banner rect is the same on every shop spec, and `shop_gift_claimed` is already the captured claimed banner, so a new full-page state per tab was not captured.

`ParityViewer.ApplyOverrides` calls `UseClaimedGiftBanner` when the page is shop and `CanClaimDailyGift` is false, before the unchanged-overrides return. Specs whose banner class already contains `claimed` are left alone, so `shop_gift_claimed` keeps its own nodes.

The transplanted element ids are part of the layer-cache key (`styleOverrideIds` in `DynamicSetSame`). They are not marked dynamic. A text-value change does not rebake. Adding or clearing the id set does.

Passing filtered run after that change (`shop-gift-editmode-fix3.xml`): 8 passed, 0 failed, 2.850 s. The banner-region `Color32` buffers match `shop_gift_claimed` for all six shop specs, with and without the claimed text overrides, plus the stamped rings case. Singularities `Draw(4000)` matches `shop_gift_claimed` `Draw(4000)`. Singularities at 1500 ms matches 4000 ms. `shop_gift_claimed` pixels and `CacheBuilds` stay the same when the override is requested. On `shop_skyboxes_mixed`, `CacheBuilds` increases when the override is applied and when it is cleared, and stays put when only the title string changes.

A second press still does not add a toast or a sound. The claimed button is the grey claimed style. The lead will ask whether a "Come back tomorrow" toast should be added.
